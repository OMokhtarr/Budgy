# App Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the Android app, Budgy can ask for the phone's own unlock (fingerprint, face or phone PIN) when it opens
and when it comes back after a chosen time away, with a cover hiding the app while locked.

**Architecture:** A pure lock controller (`src/core/lock/lockController.ts`) owns the rules: when to cover, when to
lock, and ignoring the pause/resume Android fires around Budgy's own prompt. `LockProvider` feeds it Capacitor's
`pause`/`resume` events and the saved setting, and renders `LockCover` above everything. The prompt comes from
`@capgo/capacitor-native-biometric`. A tiny app-local Capacitor plugin (`AppPrivacy`) hides the recent-apps
preview on Android 13+.

**Tech Stack:** React 19 + Ionic 8, Capacitor 8, Vitest (node environment, `src/**/*.test.ts` only),
i18next (`src/core/i18n/locales/{en,ar}.json`), Java for the Android plugin.

**Spec:** `docs/superpowers/specs/2026-11-20-app-lock-design.md`

## Global Constraints

- Android only for now. On the web (`!Capacitor.isNativePlatform()`), nothing locks and the Settings section is hidden.
- Plugin: `@capgo/capacitor-native-biometric` pinned at exactly `8.9.3`.
- Prompt: `verifyIdentity({ title, allowedBiometryTypes: [BiometryType.MULTIPLE, BiometryType.DEVICE_CREDENTIAL] })`.
  That gives `BIOMETRIC_WEAK | DEVICE_CREDENTIAL`, a plain prompt with no crypto object.
- Screen-lock check: `isAvailable({ useFallback: true })` → `deviceIsSecure`. A failed check counts as "not secure",
  so Budgy opens. The lock never shuts the owner out (my call).
- Lock-after choices: `0`, `60_000`, `300_000` ms. The default is `60_000`. Off by default.
- Settings key `appLock: { enabled: boolean; afterMs: number }` in `budgy-settings`. It is **not** in `BACKUP_KEYS`,
  so it is never synced or backed up.
- Recent-apps preview: `Activity.setRecentsScreenshotEnabled(false)` on API 33+ only. Never `FLAG_SECURE`.
- The lock is free (no `useRequirePro`).
- English and Arabic text for every new string. The cover must work in RTL and dark mode.

## Review Focus

1. **Coming back from Budgy's own prompt.** The prompt is a separate Android activity, so `pause`/`resume` fire around
   it. The app must not re-lock or show a second prompt. Covered by Task 1's "ignores pause/resume during a prompt"
   tests.
2. **A start immediately followed by pause/resume** (the prompt opening on start). There must be exactly one prompt.
   Covered by the same tests.
3. **The phone's screen lock is removed after the app lock was turned on.** Budgy opens, and the setting stays on.
   Task 1, "opens without a prompt when the phone has no screen lock".
4. **The prompt is cancelled.** The cover stays and Unlock prompts again. Task 1, "stays locked when the prompt is
   cancelled".
5. **Turning the lock off or on from Settings.** The pause/resume around that prompt must not put the cover up.
   Task 1, "confirm ignores pause/resume and keeps the app open".

### Task 1: Lock rules and controller (pure, TDD)

**Files:**
- Create: `src/core/lock/lockController.ts`
- Test: `src/core/lock/lockController.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const LOCK_AFTER_OPTIONS = [0, 60_000, 300_000] as const;
  export const DEFAULT_LOCK_AFTER_MS = 60_000;
  export interface AppLockSettings { enabled: boolean; afterMs: number }
  export type LockView = 'open' | 'covered' | 'locked';
  export type ConfirmResult = 'ok' | 'cancelled' | 'no-screen-lock';
  export interface LockDeps {
    now(): number;
    settings(): AppLockSettings;
    isSecure(): Promise<boolean>;
    verify(): Promise<boolean>;          // true = unlocked; any failure/cancel = false
    onView(view: LockView): void;
  }
  export interface LockController {
    view(): LockView;
    start(): void;                       // app start
    pause(): void;                       // Capacitor 'pause'
    resume(): void;                      // Capacitor 'resume'
    unlock(): Promise<void>;             // the cover's Unlock button, and the auto-prompt
    confirm(): Promise<ConfirmResult>;   // Settings: turning the lock on or off
  }
  export function createLockController(deps: LockDeps): LockController;
  ```

Rules the tests pin:
- `start()`: enabled → `'locked'` + `unlock()`; disabled → `'open'`.
- `pause()`: ignored while a prompt is open. Otherwise, if enabled, record `awayAt = now()` and go to `'covered'`.
- `resume()`: ignored while a prompt is open, or when there's no `awayAt`. Otherwise, if `now() - awayAt >= afterMs`,
  go to `'locked'` and `unlock()`; if not, go to `'open'`. Clear `awayAt` either way.
- `unlock()`: if a prompt is already open, do nothing. If `!(await isSecure())`, go to `'open'` without a prompt.
  Otherwise set prompting, `await verify()`, then clear prompting; true → `'open'`, false → stay `'locked'`.
- `confirm()`: same prompting guard. `!isSecure` → `'no-screen-lock'`; then `verify()` → `'ok'` / `'cancelled'`.
  It never changes the view.
- `onView` fires only when the view actually changes.

  mutable `settings`, `isSecure` resolving a flag, and `verify` returning a promise the test resolves by hand (so it

- Modify: `android/app/src/main/java/com/budgymoney/app/MainActivity.java`

**Interfaces:**
- Consumes: `AppLockSettings`, `DEFAULT_LOCK_AFTER_MS` (Task 1).
- Produces:
  - `Settings.appLock: AppLockSettings`, with `DEFAULTS.appLock = { enabled: false, afterMs: DEFAULT_LOCK_AFTER_MS }`.
    The doc comment says it's per device and not synced (like `smsImport`). Change it with
    `update({ appLock: { ...appLock, ... } })`.
  - `native.ts`:
    ```ts
    export const lockSupported: boolean;                  // Capacitor.getPlatform() === 'android'
    export function isPhoneSecure(): Promise<boolean>;    // isAvailable({useFallback:true}).deviceIsSecure; catch → false
    export function verifyOwner(title: string): Promise<boolean>; // verifyIdentity (Global Constraints); resolve → true, reject → false
    export function setRecentsHidden(hidden: boolean): Promise<void>; // AppPrivacy plugin; no-op off Android; catch and ignore
    ```
    `AppPrivacy` is registered with `registerPlugin<{ setRecentsHidden(o: { hidden: boolean }): Promise<void> }>('AppPrivacy')`,
    like `src/features/sms/native.ts`.
  - Java `@CapacitorPlugin(name = "AppPrivacy")` with `@PluginMethod setRecentsHidden(call)`. It reads
    `call.getBoolean("hidden", false)`. On `Build.VERSION.SDK_INT >= 33` it runs
    `getActivity().setRecentsScreenshotEnabled(!hidden)` on the UI thread. It always resolves. Add a class comment
    saying why it isn't `FLAG_SECURE`.
  - `MainActivity.onCreate(Bundle)`: `registerPlugin(AppPrivacyPlugin.class);` before `super.onCreate(savedInstanceState)`.

### Task 3: LockProvider and the locked cover

**Files:**
- Create: `src/core/lock/LockProvider.tsx`
- Create: `src/core/lock/LockCover.tsx`
- Modify: `src/index.css` (the `.b-lock-cover` styles)
- Modify: `src/App.tsx` (wrap the content inside `<IonApp>` with `<LockProvider>`)
- Modify: `src/core/i18n/locales/en.json`, `ar.json` (new `lock` group)

**Interfaces:**
- Consumes: `createLockController`, `LockView`, `ConfirmResult` (Task 1); `lockSupported`, `isPhoneSecure`,
  `verifyOwner`, `setRecentsHidden` (Task 2); `useSettings().appLock`.
- Produces:
  ```ts
  export function useAppLock(): { supported: boolean; confirm(): Promise<ConfirmResult> };
  ```

Behaviour:
- **Set-up.** When `lockSupported` is false the provider renders only its children, and `confirm()` resolves
  `'cancelled'`.
- **Controller.** On Android, create one controller (in a ref) whose `settings()` reads the latest `appLock` from a
  ref. Its `verify` is `verifyOwner(t('lock.promptTitle'))`.
- **Start.** Call `start()` once, on mount. The first view state is computed synchronously from the saved setting, so
  the cover is in the first render when the lock is on.
- **Events.** Subscribe to `CapApp.addListener('pause' | 'resume')` and remove them on unmount.
- **Recent-apps preview.** `useEffect` on `appLock.enabled` → `setRecentsHidden(enabled)`.
- **Cover.** Render `<LockCover view={view} onUnlock={() => void controller.unlock()} />` after the children. When
  the view is `'open'`, the cover renders nothing.
- **Back.** While the view isn't `'open'`, register an `ionBackButton` handler at priority `1000` (above overlays'
  100) that calls `CapApp.exitApp()`.
- **What the cover shows.** A full-screen fixed `div.b-lock-cover` with `z-index: 100000` (above Ionic overlays)
  and the `--b-bg` background. It shows `/icon.png` at the splash's size (112px, radius 28px). When the view is
  `'locked'`, it also shows the title `t('lock.locked')` and an `IonButton` with `t('lock.unlock')`. When the view
  is `'covered'`, it shows the logo only.

Copy:
- en: `"lock": { "promptTitle": "Unlock Budgy", "locked": "Budgy is locked", "unlock": "Unlock" }`
- ar: `"lock": { "promptTitle": "افتح قفل Budgy", "locked": "Budgy مقفل", "unlock": "فتح القفل" }`

### Task 4: Settings → Security section

**Files:**
- Create: `src/features/settings/AppLockSettingsSection.tsx`
- Modify: `src/features/settings/SettingsPage.tsx` (render the section after the General list, before rates)
- Modify: `src/core/i18n/locales/en.json`, `ar.json` (`lock` group)

**Interfaces:**
- Consumes: `useAppLock()` (Task 3); `useSettings().appLock` and `update`; `LOCK_AFTER_OPTIONS` (Task 1).

Behaviour:
- **When it shows.** The section renders nothing unless `useAppLock().supported` is true.
- **Layout.** An `IonList inset` with the header `t('lock.security')`. It has:
  - an `IonToggle` row `t('lock.toggle')` with the hint `t('lock.toggleHint')`;
  - when enabled, an `IonSelect` (action-sheet) `t('lock.after')` over `LOCK_AFTER_OPTIONS`, labelled
    `lock.afterImmediately` / `lock.afterOneMinute` / `lock.afterFiveMinutes`.
- **The toggle never changes the setting by itself.** On a change, call `confirm()`:
  - `'ok'` → `update({ appLock: { ...appLock, enabled: next } })`;
  - `'no-screen-lock'` → an alert with `t('lock.noScreenLock')`;
  - `'cancelled'` → nothing.
  Afterwards, re-render the toggle from the saved value. Give it a `key`, like the currency select's
  `currencyKey`, so it bounces back after a cancel.
